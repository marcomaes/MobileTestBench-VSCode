# Porting guide

How the Kotlin plugin maps onto this extension, and how to port the next file.

## Mapping

| IntelliJ plugin | VS Code extension |
|---|---|
| `core/**` (pure Kotlin) | `src/core/**` (pure TypeScript, same folders and file names in camelCase) |
| `DeviceServices.kt` | `src/deviceServices.ts` |
| `ui/DeviceViewerPanel.kt`, `ScreenView.kt`, `InspectorPanel.kt` | `src/extension/deviceViewer.ts` (host) + `src/webview/mirror.ts` (page) |
| `ui/<X>Panel.kt` (a `DeviceToolTab`) | `src/extension/tools/<id>.ts` (host half, `ToolHost`) + `src/webview/tools/<id>.ts` (page half, `ToolView`) |
| Swing components, `JBTabs` | DOM built with `src/webview/ui.ts` helpers, VS Code theme variables |
| `settings/*` | `src/settings.ts` + `package.json` `contributes.configuration` + `src/extension/settings.ts` |
| `GrpcEmulatorLink` (grpc-java) | `src/android/grpcEmulatorLink.ts` (`@grpc/grpc-js`, same `src/proto/emulator_controller.proto`) |
| `java.awt.image.BufferedImage` | `Frame` (encoded PNG/JPEG bytes + size, `src/core/image/dimensions.ts`); pixels via `pngjs` / `jpeg-js` only where an algorithm needs them (ImageDiff, Contrast) |
| `javax.xml` | `src/core/xml.ts` |
| Gson | `JSON.parse` with narrow type guards |
| IntelliJ notifications, dialogs, file choosers | `vscode.window.*` in the host half, reached through a `ToolHost.handle` method |
| Editor action `ShowLocatorAction` | command `mobileTestBench.showLocator` |
| Project service `ProjectViewState` | `context.workspaceState` |

## Rules

1. Header line `// ported-from: <kotlin path under the Kotlin root>` on every ported file, one per Kotlin file it covers. Tests: `// ported-from: test:core/XTest.kt`.
2. `Foo.kt` becomes `foo.ts` in the same folder. Keep public names so a reviewer can diff the two files side by side.
3. Blocking Kotlin calls are `async`; `null` is `undefined`; `Duration` is milliseconds with an `Ms` suffix.
4. Port the Kotlin tests with the same names. Use `fixture('name')` for resources; if a fixture is missing run `npm run sync:fixtures`.
5. Never edit `test/fixtures`. Never edit the plugin repository.
6. A Device Tools tab is two files with the same id. The host half owns every process, file system and VS Code API call. The webview half only draws and calls `api.request(method, params)`. Long running work (log streams, polling) pushes events with `ctx.emit` between `shown` and `hidden`.
7. Add wiring (factories for backends) to `src/deviceServices.ts` with `Edit`, never rewrite the file.
8. New settings go in `src/settings.ts` and `package.json` together (a test checks they agree).
9. When the extension must behave differently, keep the Kotlin semantics and leave one comment saying what differs and why.

## Status

`docs/PARITY.md` (generated by `npm run sync -- report`) lists every Kotlin file with its TypeScript counterpart and status. Anything `missing` there is still to port.

Known gaps in the foundation:
- iOS simulator without mobilecli (simctl + WebDriverAgent) is not ported: `IosSimulatorSession`, `WdaClient`.
- Emulator gRPC link (`GrpcEmulatorLink`): the `EmulatorLink` interface exists, the implementation is a separate task.
- Reconnect, Device Power, freeze, orientation toggle, project state restore, coordinate overlay and the foreground app poll in `DeviceViewerPanel` are not in `deviceViewer.ts` yet.
